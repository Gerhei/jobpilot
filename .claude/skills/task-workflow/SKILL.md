# Рабочий процесс через задачи (Task-Driven Development)

## Суть

Перед любой задачей с 3+ шагами — создать `todo.md` в корне проекта.
Работать пошагово. Одна задача за раз. Не переключаться, пока текущая не закрыта.

## Формат todo.md

```
## Цель: <краткое описание задачи>

### Задачи
- [x] Выполненная задача
- [~] Текущая задача (В РАБОТЕ)
- [ ] Ожидающая задача
- [!] Заблокировано: <причина>

### Обнаруженные по ходу
- [ ] Проблема, найденная во время работы
```

## Правила

- Поставить `[~]` ДО начала работы над задачей
- Отметить `[x]` ТОЛЬКО после прохождения тестов
- Одна задача за раз — не переключаться, пока текущая не закрыта
- Найдена новая проблема → добавить в «Обнаруженные по ходу», не прерывать текущую задачу

## Правило исправления багов

Один баг за раз:
1. Найти баг
2. Исправить
3. Запустить тесты
4. Только потом — следующий баг

Никогда не исправлять несколько багов одновременно.

## Чекпоинт перед отметкой «готово»

Перед отметкой `[x]` — запустить проверку качества (команды определены в CLAUDE.md):

```bash
uv run ruff check . --fix
uv run ruff format .
uv run pytest tests/ -v
```

Все три должны завершиться без ошибок.

После завершения написать:
> ✓ Готово: [задача]. Состояние: [кратко]. Следующая: [задача]
